# 리뷰 제안 기준 (AI용)

타임라인 기록을 읽고, 사용자가 문서로 옮길 만한 내용을 고르기 위한 기준입니다. 이 파일은 코드가 해석하지 않으므로 자유롭게 고칠 수 있습니다. 기준은 임시이며, 써 보면서 조정합니다.

## 고르는 순서

1. 같은 주제의 기록을 묶습니다. 기록 하나하나가 아니라 주제 하나를 제안 한 건으로 만듭니다.
2. 다음 중 하나에 해당하는 주제만 후보로 삼습니다.
   - 나중에 "왜 이렇게 정했지?"에 답해야 하는 결정
   - 다시 찾아볼 가능성이 큰 값, 명령, 절차, 문제 해결 방법
   - 작동 원리를 새로 이해하게 된 내용
3. 다음은 후보에서 뺍니다.
   - 진행 상황만 적은 기록 (예: "2단계 완료")
   - 이미 문서에 반영된 것으로 보이는 내용
   - 거절한 주제와 같은 내용
   주어진 회고 글(`<reflection>`)이 있으면 거기에 나온 내용을 먼저 고릅니다. 사용자가 직접 생각해 적은 내용이기 때문입니다. 회고 글에만 있고 기록에 없는 내용이어도 후보가 됩니다. 앞으로 할 일과 그 시점의 감상은 고르지 않습니다.
4. 새 문서를 만들기 전에, 주어진 문서 목록에서 갱신할 문서를 먼저 찾습니다.
5. 여러 날에 걸쳐 나온 주제를 우선합니다. 다만 하루에 몰린 주제도 위의 조건에 맞으면 후보입니다.

억지로 다섯 건을 채우지 않습니다. 옮길 만한 내용이 없으면 제안하지 않습니다.

## 문서 종류

| 종류 | 답하는 질문 |
|:---|:---|
| 참고 | 그 값이나 사실이 무엇이었지? |
| 이해 | 왜 이렇게 작동하지? |
| 방법 | 어떻게 하지? |
| 판단 | 왜 그렇게 보았거나 정했지? |

종류를 판단하기 어려우면 비워 둡니다.
