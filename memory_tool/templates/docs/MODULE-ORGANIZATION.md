# Module Organization

> How documents are shaped and arranged in memory_tool

A module is a document. It is the writer's text, so the tool adds as little as possible and keeps its guidance outside the file.

---

## Where something belongs

| It is... | Put it in |
|:---|:---|
| A daily note or a small decision | The timeline: `m "Decision: ..."` |
| Something you will look up, or need to explain later | A document |
| Something you intend to do | A planning tool: `mplan`, or Goal Loop if you use it |

Before creating a document, check whether updating an existing one is enough: `ms "topic"`.

---

## Document types

The type is optional. Leave it empty when unsure, or when a document mixes several.

| Type | Answers | Updated when |
|:---|:---|:---|
| 참고 | What was that value or fact? | The subject changes |
| 이해 | Why does this work this way? | Your understanding deepens |
| 방법 | How do I do this? | Applying it fails |
| 판단 | Why did I see it, or decide it, that way? | Never rewritten; a new judgment replaces it |

- Research still in progress is a 참고 document. Put unresolved questions under `## 열린 질문`. When a conclusion is reached, write a 판단 document and link to it.
- A situation you keep tracking is a 참고 document with `stale_after`. Predictions and interpretations of it are 판단 documents.

## Document shape

`mmodule create` writes frontmatter and a title. No section is required.

```markdown
---
type: 판단
description: One sentence on what this document answers
tags: []
generated:
  by: human:example
  at: 2026-11-05T10:00:00+09:00
---

# Title
```

| Field | Use |
|:---|:---|
| `type` | One of the types above, or empty |
| `description` | One sentence. If one sentence is not enough, consider splitting the document |
| `tags` | Tags |
| `generated.by` | `human:<id>` or `<producer>/<version>`, to tell written text from generated text |
| `sources` | Add when the document rests on code or other material. `mcheck` verifies local paths |
| `stale_after` | Add when the content has a date to be looked at again |
| `title` | Add only when it differs from the file name |

Documents without `type`, or with other frontmatter keys, are fine. Existing documents need no change: sections such as `Related Files`, `Decisions` and `Current` are still read where they exist.

### Help with writing

Guidance is not placed in the document. `mmodule guide` prints the questions and checks for each type, and the `mt-write` skill uses them in conversation. To change a guide, put your own copy in `<base>/guides/`.

## Children

A document is one file: `topic.md`. Creating a child moves it into a folder of its own name.

```
topic.md          ->   topic/topic.md
                       topic/child.md
```

- The file name stays the same, so `[[topic]]` links keep working. Links that spell out the old path can be fixed with `mmodule relink`.
- The parent's content is not touched. It gets no table of contents unless you write one.
- `rename` and `archive` handle the folder as one subject, children included.
- A folder without a parent document is fine, and so is `topic.md` beside `topic/` when made by hand.
- `index.md` is not generated.

Children inherit nothing. A folder groups documents, and links relate them.

---

## Splitting and merging

`mmodule audit` lists candidates and changes nothing. Length alone is not a reason to split: a long lookup table is fine. Split when the sections answer different questions.

Avoid splitting before the boundaries are clear. A long document that answers one question is better than several short ones that always change together.

## Commands

```bash
mmodule create "topic" --type 참고 --desc "One sentence"
mmodule guide 참고                 # Questions and checks for a type
mmodule tree                       # View hierarchy
mmodule audit                      # Split and merge candidates
mmodule suggest-links "topic"      # Candidates by path and links
mmodule suggest-links "topic" --ai # Candidates by content
mmodule check-links                # Find broken links
mcheck                             # Verify paths in sources and Related Files
```
