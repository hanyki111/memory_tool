- 작성일: 2026-11-07
- 상태: 0.1을 구현했으며(2026-11-07, 4절), 휴대폰에서의 확인과 병합이 남았습니다. 브랜치는 `feature/android-capture`입니다.
- 앞선 작업: `docs/handoff/2026-11-05-ai-and-module-format.md`(문서 형식, 리뷰, JSON 출력, VS Code 화면)

## 1. 배경

사용자는 밖에서 휴대폰으로 타임라인에 기록하려고 합니다. 2026-11-06~07에 검토한 방법과 결과는 다음과 같습니다.

| 방법 | 결과 |
|---|---|
| Termux + Termux:Widget + Termux:API로 SSH 실행 | Play 프로텍트가 설치를 막았고, F-Droid는 "오래된 Android 기반이라 자동 업데이트 불가"로 안내했습니다. 사용자는 기록 버튼 하나를 위해 리눅스 환경을 돌리는 것이 맞지 않다고 보았습니다 |
| 휴대폰 Obsidian에 직접 기록 | PC의 Obsidian이 켜져 있어야 PC 파일로 동기화됩니다. 같은 날짜 파일을 휴대폰과 PC의 `m`이 따로 고치면 충돌 사본이 생길 수 있습니다 |
| HTTP Shortcuts + PC 기록 서버 | 새 포트를 외부에 열고 토큰과 HTTPS를 갖춰야 합니다 |
| **직접 만든 SSH 기록 앱** | **채택했습니다.** 이미 열려 있는 SSH를 쓰고, 모든 기록이 PC의 `m`으로 들어가며, 보내지 못한 기록을 휴대폰에 보관할 수 있습니다 |

### 확인한 환경

- **PC(Windows):** OpenSSH 서버가 자동 시작으로 실행 중입니다. 포트는 2222, 기본 셸은 PowerShell 7(`C:\progra~1\PowerShell\7\pwsh.exe`)입니다. 사용자는 공유기 포트 포워딩과 DDNS로 밖에서 접속하고 있습니다.
- **계정:** `shy61`은 관리자 그룹에 속합니다. 그래서 공개 키는 `~/.ssh/authorized_keys`가 아니라 `C:\ProgramData\ssh\administrators_authorized_keys`에 넣어야 하고, 이 파일의 권한은 Administrators와 SYSTEM만으로 제한해야 합니다(`sshd_config`의 `Match Group administrators`).
- **등록된 키:** 2026-11-07 기준으로 없습니다. 노트북(Ubuntu)도 비밀번호로 접속하고 있습니다. 비밀번호 로그인은 꺼져 있지 않습니다.
- **PC의 호스트 키 지문:** ED25519 `SHA256:V+sfV+6v7EisnnFEcDOFugdQVjmdLTpAv98HFT9R+9Y`
- **시험 기기:** 갤럭시 S22, One UI 8(Android 16)

## 2. 결정

2026-11-07에 사용자와 논의하여 정했습니다.

| 번호 | 쟁점 | 결정 |
|---|---|---|
| 1 | 명령 틀 | memory_tool 실행 방식 하나를 저장합니다. 예: `Set-Location 'E:\…\memory_notion'; python -m memory_tool {args}`. 앱이 명령과 인수를 PowerShell 작은따옴표로 감싸서(안의 `'`는 `''`로) `{args}` 자리에 넣습니다. 처음에는 기록 명령 틀만 저장하려 했으나, 0.2의 보기·수정 명령을 위해 넓혔습니다 |
| 2 | 기록 창을 여는 방법 | 앱 아이콘, 홈 화면 위젯, 빠른 설정 타일, 공유하기. 위젯은 입력칸 모양이고 누르면 홈 화면 위에 작은 입력 창이 뜹니다. 안드로이드 위젯은 글 입력 부품을 쓸 수 없기 때문입니다. 위젯에는 음성 입력 버튼과 보관 상태를 둡니다 |

| 7 | 결과 표시 | 성공은 "21:30 기록함"을 잠깐 띄웁니다. `notices`와 실패는 알림으로 띄웁니다. 다시 보내도 같은 결과가 나오는 실패(`distant_past` 등)는 "확인 필요"로 둡니다. 앱 안에 최근 보낸 기록 목록을 둡니다. `--json` 출력이 아니면 첫 줄을 보여 줍니다 |
| 8 | 지원 기기 | Android 10(API 29) 이상 |
| 9 | 범위 | 0.1 기록, 0.2 타임라인 보기·수정. 모듈 편집은 넣지 않습니다. 0.2의 설계는 0.1을 써 본 뒤 정합니다 |
| - | 설치 | 직접 서명한 APK를 휴대폰으로 옮겨 설치합니다. 사용자가 `mlog.ps1` 같은 PC 쪽 스크립트 없이, 명령을 앱에 저장하는 방식을 골랐습니다 |

**관례에 따라 정한 세부 사항**

- Kotlin, Jetpack Compose. 백그라운드 재전송은 WorkManager(네트워크 연결 조건).
- 화면 언어는 휴대폰 언어를 따릅니다(한국어, 그 밖에는 영어).
- 설정: PC 주소(DDNS), 포트, 사용자, 명령 틀, 음성 대기 시간. PC는 한 대만 지원합니다.
- 서명 키는 저장소 밖에 보관합니다. 업데이트할 때 같은 서명을 써야 앱 데이터가 유지됩니다.
- 빌드 도구는 C 드라이브 여유 공간이 적어(2026-11-07 기준 약 95% 사용) E 드라이브에 설치합니다. 전역 환경 변수는 바꾸지 않고, `android/local.properties`(저장소에 넣지 않음)와 Gradle 설정으로 경로를 지정합니다.

### 설치한 빌드 환경 (2026-11-07)

모두 `E:\dev` 아래에 있으며, 전역 환경 변수와 PATH는 바꾸지 않았습니다. 내려받은 파일은 배포처의 체크섬과 대조했습니다.

| 도구 | 위치 | 버전 | 확인 |
|---|---|---|---|
| JDK | `E:\dev\jdk-17` | Temurin 17.0.21+9 | Adoptium API의 SHA-256 |

## 3. 0.1 구현 계획

브랜치는 `feature/android-capture`입니다. 각 단계는 별도의 커밋으로 나누고, 순수 Kotlin 부분은 JVM 단위 테스트로 확인합니다. 기기 화면과 위젯, 타일은 사용자가 휴대폰에서 확인합니다.

1. **빌드 환경:** JDK 17과 안드로이드 명령줄 도구, SDK(플랫폼, 빌드 도구, platform-tools)를 E 드라이브에 설치합니다.
2. **뼈대:** `android/`에 Gradle 래퍼, 앱 모듈, Compose 설정을 만듭니다. `minSdk 29`, `targetSdk`는 설치한 최신 플랫폼으로 합니다.
3. **핵심 논리(안드로이드 API 없음):**
   - PowerShell 인용, 명령 틀 채우기(`{args}`), 기록 인수 만들기(`record --json --date --time -- 내용`)
   - 결과 해석: JSON의 `ok`, `entry`, `notices`, `code`, JSON이 아닌 출력
   - 보관 항목의 상태 전이: 보낼 차례, 보냄, 확인 필요, 실패 종류에 따른 재전송 여부
4. **SSH:** ED25519를 지원하는 라이브러리를 고르고, 키 생성과 암호화 보관, 호스트 키 지문 확인(처음 확인 후 저장, 바뀌면 거부)을 구현합니다. 실패를 "명령 전송 전"과 "명령 전송 후"로 나눕니다.
5. **저장:** 보관 목록과 최근 보낸 기록, 설정을 저장합니다.
6. **입력 창:** 홈 화면 위의 작은 입력 창(투명 액티비티), 음성 입력과 3초 대기, 공유하기 받기.
7. **진입점:** 앱 아이콘, 빠른 설정 타일, 홈 화면 위젯(입력칸 모양, 음성 버튼, 보관 상태).
8. **백그라운드 전송과 알림:** WorkManager 재전송, 성공 문구, 안내와 실패 알림, 알림 권한 요청(Android 13 이상).
9. **설정 화면:** PC 주소, 포트, 사용자, 명령 틀, 공개 키 보기·공유, 지문 확인, 연결 시험 버튼.
10. **서명과 패키징, 문서:** 서명 키 생성(저장소 밖), 릴리스 APK, `android/README.md`, 루트 `README.md`, `CHANGELOG.md`.

**회귀 테스트 필수 사례(JVM)**

- 작은따옴표, 큰따옴표, `$`, `;`, `` ` ``, `%`, 한글, 이모지가 든 내용이 PowerShell 작은따옴표 문자열로 바르게 감싸집니다.
- 줄바꿈은 공백으로 바뀝니다. 타임라인 기록은 한 줄입니다.
- `-`로 시작하는 내용 앞에 `--`가 붙습니다.
- 명령 틀에 `{args}`가 없으면 설정 단계에서 거부합니다.
- 결과 해석: 성공, `notices`가 있는 성공, 실패 코드, JSON이 아닌 출력, 빈 출력.
- 접속 전 실패는 재전송 대상이고, 명령 전송 후 실패와 `distant_past` 등은 "확인 필요"가 됩니다.

**사용자가 휴대폰에서 확인할 것**

1. APK 설치(Play 프로텍트 경고에서 "그래도 설치"가 가능한지)
2. 공개 키를 PC에 등록한 뒤 첫 접속에서 지문이 1절의 값과 같은지
3. 한글과 특수 문자가 든 기록이 PC 타임라인에 그대로 들어가는지(PowerShell과 Python을 거치는 경로)
4. 위젯, 빠른 설정 타일, 공유하기, 음성 입력
5. 비행기 모드에서 기록한 뒤 연결했을 때, 적은 시각으로 들어가는지

**이번 계획에서 하지 않는 것**

- 0.2 타임라인 보기·수정(설계는 0.1 이후), 모듈 편집
- PC 여러 대, Play 스토어 배포
- PC의 비밀번호 로그인 끄기. 휴대폰과 노트북의 키 접속을 모두 확인한 뒤 사용자가 진행합니다

## 4. 0.1 구현 결과

3절의 열 단계를 모두 커밋했습니다. JVM 테스트 28개가 통과합니다(`.\gradlew testDebugUnitTest`). 서명한 설치 파일은 `android/app/build/outputs/apk/release/app-release.apk`(26.5MB)입니다. 화면, 위젯, 타일, 음성 입력, 키 저장소는 안드로이드에서만 동작하므로 확인하지 못했습니다.

### 계획과 달라진 점

- **명령은 Base64로 보냅니다.** 앱이 완성한 명령을 Base64로 바꾸고, PC에는 `iex ([Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('…')))`만 보냅니다. 처음에는 작은따옴표로 감싼 명령을 그대로 보냈는데, `pwsh -c`에 명령을 넘기는 과정에서 큰따옴표가 사라졌습니다. Windows의 OpenSSH도 같은 방식으로 PowerShell에 명령을 넘기므로 같은 일이 생길 수 있습니다. Base64는 영문자, 숫자, `+ / =`뿐이라 어떤 명령줄을 거쳐도 바뀌지 않고, 한글이 코드 페이지를 거치는 문제도 함께 사라집니다. 풀린 명령은 출력 인코딩을 UTF-8로 정하고 실행됩니다.
- **둥근 작은따옴표도 감쌉니다.** PowerShell은 `‘ ’ ‚ ‛`도 작은따옴표로 읽습니다. 휴대폰 키보드가 이 문자를 자주 넣으므로, `'`와 똑같이 두 번 씁니다.
- **명령 틀의 인수에는 항상 `--json`이 들어갑니다.** 2절 7번의 "`--json`이 없으면 첫 줄을 보여 준다"는 경우는 생기지 않습니다. JSON이 아닌 응답은 Python이 없거나 명령 틀이 잘못된 경우이며, "확인 필요"로 둡니다.
- **SSH 라이브러리는 JSch(mwiede 판)와 Bouncy Castle입니다.** 안드로이드의 Java 암호 기능에는 Ed25519와 X25519가 없어서, `ssh-ed25519`, `keypairgen.eddsa`, `xdh`를 Bouncy Castle 구현으로 고정했습니다. JVM 테스트도 같은 구현을 쓰게 하여, 테스트가 휴대폰과 같은 경로를 시험합니다. JSch는 Ed25519 개인 키를 기본 PEM 형식으로 쓰지 못해서 OpenSSH 형식(`writeOpenSSHv1PrivateKey`)을 씁니다.
- **기록을 보내지 못한 이유를 둘로 나눕니다.** 키가 거부되었거나 지문이 바뀌었거나 설정이 비어 있으면, 기다려도 해결되지 않으므로 알림으로 한 번 알리고 자동 재전송을 멈춥니다.
- **백업과 기기 간 이전에서 앱 데이터를 뺍니다.** Android 12부터 `allowBackup="false"`만으로는 기기 간 이전을 막지 못합니다. 개인 키를 감싼 키 저장소의 키는 옮겨지지 않으므로, 옮겨진 키는 열 수 없습니다. 열지 못하면 새 키를 만듭니다.
- **서명 키는 `E:\dev\keys\memory-capture.jks`이고, 비밀번호는 같은 폴더의 `memory-capture.properties`에 있습니다.** 업데이트할 때 같은 키로 서명해야 하므로 이 두 파일을 잃지 않아야 합니다. 저장소에는 넣지 않습니다.

### 구현 중 발견한 문제

- **memory_tool이 Windows에서 인수를 펼쳤습니다(1.5.1에서 수정).** Click은 Windows에서 `sys.argv`로 받은 인수의 `$HOME`, `%USERNAME%`, `*.py`를 펼칩니다. 휴대폰 앱의 전 과정을 실제 memory_tool로 시험하다가 `$HOME`이 경로로 바뀐 것을 보고 찾았습니다. CLI, VS Code 확장, Obsidian 플러그인 모두 해당합니다. 모든 진입점이 `windows_expand_args=False`로 시작하도록 고쳤습니다(`memory_tool/cli.py`의 `run`).
- 이 버전의 Gradle 플러그인은 빌드 도구 35.0.0을 스스로 내려받습니다. 설치한 36.1.0과 함께 둡니다.

### 시험한 것

- PowerShell 인용: 작은따옴표와 둥근 작은따옴표, `$`, `;`, 역따옴표, `%`, 한글, 이모지
- 이 PC의 실제 `pwsh`를 거쳐 Python에 인수가 그대로 들어가고, Python의 UTF-8 출력이 그대로 돌아오는지
- 같은 경로로 이 저장소의 memory_tool을 실행해, 합성 지식 베이스에 기록이 적은 그대로 들어가는지
- Apache MINA sshd를 상대로 한 SSH: 지문 확인, OpenSSH 형식의 지문, 다른 지문과 등록되지 않은 키의 거부(명령 전송 전), 서버 없음, 종료 상태 없이 끝난 명령(확인 필요), 0이 아닌 종료 상태
- 보관 목록의 상태 전이와 저장 형식

### 사용자가 휴대폰에서 확인할 것

3절의 다섯 가지입니다. 설치와 설정은 `android/README.md`를 따릅니다.

## 5. 휴대폰 시험과 0.1.1, 0.1.2 수정

갤럭시 S22(One UI 8)에서 설치, 키 등록, 지문 확인, 연결 시험, 기록, 위젯, 타일, 공유하기, 음성 입력을 확인했습니다. 시험하면서 전송 방식의 문제 두 가지가 드러나 고쳤습니다.

- **0.1.1: 연결이 돌아와도 보내지 않았습니다.** 비행기 모드를 끄는 것만으로는 보내지 않고, 앱을 열어야 보냈습니다. 보낼 기록이 있는 동안 PendingIntent로 네트워크 연결 알림을 등록해서(인터넷이 확인된 네트워크만), 앱이 꺼져 있어도 깨어나도록 했습니다. 전송은 우선 실행 작업(expedited work)으로 실행하고, 재시도 간격은 15초씩 늘려 5분을 넘지 않게 했습니다. 한 기록을 보내는 동안 새 기록을 쓰면 같은 기록이 두 번 보내질 수 있었는데, 전송을 한 번에 하나씩만 실행하도록 막았습니다.
- **0.1.2: 연결 직후의 실패와 끊긴 연결.** 깨어난 직후에는 DDNS 주소 조회가 실패했고("The PC's address could not be found"), 배터리 최적화가 켜져 있으면 지연 실행되는 재시도가 오래 미뤄졌습니다. 같은 작업 안에서 5초, 10초, 20초를 기다리며 다시 시도하도록 했습니다. 또 모바일 데이터에서 Wi-Fi로 바뀌면서 보낸 직후 연결이 끊겼습니다. 이런 기록은 CHECK 상태로 두고, PC에서 `day --json -- <날짜>`를 실행해 같은 시각, 같은 글이 있는지 확인한 뒤 보낸 것으로 처리하거나 다시 보냅니다.
- **확인 결과:** 배터리 최적화를 켠 상태에서 비행기 모드로 기록한 뒤 비행기 모드를 끄자, 앱을 열지 않아도 "PC에 이미 기록되어 있음"이 떴고 기록은 한 번만 들어갔습니다. JVM 테스트는 33개입니다.
- 시험 기록은 이 저장소의 2026-11-07 타임라인에 들어갔습니다.
- 다음 작업은 0.2(타임라인 보기와 수정)이며, 기능을 마친 뒤 UI를 다듬는 단계를 따로 둡니다.

## 6. 0.2: 타임라인 보기, 검색, 수정 (CLI 1.6.0)

### 결정

- **범위:** 보기와 수정에 키워드 검색을 더합니다. 오프라인 보기는 휴대폰에 업무 기록 사본이 남으므로 써 본 뒤 판단합니다.
- **기록 지정:** 날짜, 시각, 원래 글로 지정합니다. 그사이 PC에서 바뀌었으면 `not_found`로 거절하고 덮어쓰지 않습니다. 줄 순서는 다른 기록을 고칠 위험이 있고, ID는 파일 형식을 바꾸므로 쓰지 않습니다.
- **날짜 변경:** 허용합니다. 새 날짜의 파일에 먼저 추가한 뒤 원래 파일에서 지웁니다.
- **화면:** 타임라인이 첫 화면이고, 위에 검색창과 톱니바퀴(설정)를 둡니다. 새 기록은 버튼 없이 하단 입력란에서 바로 보냅니다(사용자 요청: 한 단계 줄이기). 설정에 글자 크기를 둡니다.

### 구현 중 발견한 문제

- **0.1.2의 확인이 태그 붙은 기록을 놓쳤습니다.** `record`는 태그를 정리해 다시 씁니다(`a #x` → `[x] a`). 적은 글을 그대로 비교하면 "없음"이 되어 다시 보냅니다. 확인은 이제 `entry find`로 PC에 묻습니다.
- **`ms --type`은 언제나 빈 결과였습니다.** 형식 필터의 기준 폴더가 어긋나 있었습니다.
- **검색 캐시가 지식 베이스를 섞었습니다.** 홈 폴더의 캐시 키에 지식 베이스가 없었습니다. 앱은 `--no-cache`로 검색합니다(고친 직후의 검색이 옛 글을 보이지 않도록).
- `record`와 다른 명령은 캐시를 비우지 않으므로, PC에서도 기록 직후 한 시간 동안은 같은 검색어의 결과에 새 기록이 빠질 수 있습니다. 이번에는 고치지 않았습니다.

### 시험한 것

- CLI 923개: `entry`의 찾기(적은 글과 저장된 글, 태그 형식), 수정(글, 시각 정렬과 손으로 적은 줄, `-`로 시작하는 글, 날짜 이동, 파일이 없는 날짜, `future_time`, `distant_past`와 `--force`, 빈 글), 삭제, `--type`, 캐시 분리
- 앱 JVM 40개: 인수와 응답 읽기, 날짜 병합과 정렬, 이 PC의 실제 pwsh와 memory_tool로 기록 → 찾기 → 날짜 조회 → 검색 → 날짜 이동 수정 → 같은 수정의 거절 → 삭제
- 화면(목록, 스크롤, 편집 창, 입력란, 글자 크기)은 휴대폰에서 확인해야 합니다.

### 휴대폰 시험과 0.2.1

- **잘 된 것:** 타임라인 첫 화면, 검색, 편집(글, 날짜, 시각, 삭제), 글자 크기, PC에서 먼저 고친 기록의 거절
- **첫 화면이 목록 끝에서 열렸습니다.** 처음의 "불러오는 중" 항목에 고정 키가 있어서, 목록이 그 항목을 제자리에 두려고 끝으로 갔습니다. 키를 없앴습니다.
- **보낼 기록이 화면 밖에 있었습니다.** 같은 이유로, 목록 맨 위에 끼어든 항목은 위쪽 화면 밖에 놓였습니다. 입력란 바로 위의 접힌 한 줄로 옮겼습니다.
- **사용자 요청:** 편집은 고칠 일이 드무니 길게 눌러서 하고, 짧게 누르면 안내를 띄웁니다(누를 때의 물결 효과와 길게 누를 때의 진동 포함). 글자 크기 범위는 70~200%로 넓혔습니다.
- **0.2.1 확인 결과:** 휴대폰에서 모두 잘 동작했습니다(첫 화면, 입력란 위의 보내지 않은 기록, 길게 눌러 편집, 글자 크기).
- 세련된 UI 작업은 아직 하지 않았습니다. 0.2.1을 확인하고 병합한 뒤 따로 논의합니다.

## 7. 0.3.0: UI 다듬기

### 결정

- **방향:** 세 갈래(Material You 정돈형, 글 중심의 미니멀형, 채팅형)를 합성 기록으로 그린 비교 화면에서 고른 것은 미니멀형입니다. 세로 시간선과 점을 쓰고, 태그는 Material You처럼 연한 칩으로, 입력란의 안내 문구는 "무슨 일이 있었나요?"로 정했습니다.
- **색:** 동적 색상을 포함해 여러 강조색을 설정에서 고르고, 라이트와 다크 모드를 둡니다(사용자 요청).
- **PC 설정:** 사용자가 정할 것은 폴더뿐이므로 "명령"을 "지식 베이스 폴더"로 바꿉니다(사용자 요청).

### 구현 중 발견한 문제

- **틀린 폴더에서도 memory_tool이 실행되었습니다.** `Set-Location`은 실패해도 다음 명령으로 넘어갑니다. `-ErrorAction Stop`을 붙였고, 실제 pwsh로 시험합니다.
- 폴더만 받으므로 Python의 전체 경로를 적던 방법이 없어졌습니다. `python`이 SSH 세션의 PATH에 있어야 합니다.

### 시험한 것

- 앱 JVM 48개: 폴더 명령(작은따옴표가 든 폴더, 예전 명령에서 폴더 뽑기, 틀린 폴더에서 멈추는지 실제 pwsh로), 태그 나누기, 색 대비(라이트와 다크, 모든 강조색)
- **휴대폰 확인 결과:** 모두 잘 동작했습니다(타임라인 모양, 태그 칩, 화면 모드와 강조색, 위젯과 작은 입력 창, 지식 베이스 폴더와 연결 시험).
- **갤럭시 버즈 길게 누르기:** 버즈는 휴대폰의 기본 음성 비서를 부르므로, 음성 명령 요청을 받는 입구를 두면 될 가능성은 있었습니다. 어떤 요청이 오는지 알 수 없고 빅스비나 Gemini를 잃으므로, 사용자가 포기했습니다.
