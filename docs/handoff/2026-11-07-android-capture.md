# 인수인계: 안드로이드 기록 앱

- 작성일: 2026-11-07
- 상태: 설계를 마쳤으며, 0.1 구현 전입니다. 브랜치는 `feature/android-capture`입니다.
- 앞선 작업: `docs/handoff/2026-11-05-ai-and-module-format.md`(문서 형식, 리뷰, JSON 출력, VS Code 화면)

> 이 문서와 테스트 데이터에 실제 업무 노트를 넣지 마십시오. 시험은 합성 데이터나 이 저장소의 타임라인으로 합니다.

## 1. 배경

사용자는 밖에서 휴대폰으로 타임라인에 기록하려고 합니다. 2026-11-06~07에 검토한 방법과 결과는 다음과 같습니다.

| 방법 | 결과 |
|---|---|
| Termux + Termux:Widget + Termux:API로 SSH 실행 | Play 프로텍트가 설치를 막았고, F-Droid는 "오래된 Android 기반이라 자동 업데이트 불가"로 안내했습니다. 사용자는 기록 버튼 하나를 위해 리눅스 환경을 돌리는 것이 맞지 않다고 보았습니다 |
| 휴대폰 Obsidian에 직접 기록 | PC의 Obsidian이 켜져 있어야 PC 파일로 동기화됩니다. 같은 날짜 파일을 휴대폰과 PC의 `m`이 따로 고치면 충돌 사본이 생길 수 있습니다 |
| HTTP Shortcuts + PC 기록 서버 | 새 포트를 외부에 열고 토큰과 HTTPS를 갖춰야 합니다 |
| **직접 만든 SSH 기록 앱** | **채택했습니다.** 이미 열려 있는 SSH를 쓰고, 모든 기록이 PC의 `m`으로 들어가며, 보내지 못한 기록을 휴대폰에 보관할 수 있습니다 |

### 확인한 환경

- **PC(Windows):** OpenSSH 서버가 자동 시작으로 실행 중입니다. 포트는 2222, 기본 셸은 PowerShell 7(`C:\progra~1\PowerShell\7\pwsh.exe`)입니다. 사용자는 공유기 포트 포워딩과 DDNS로 밖에서 접속하고 있습니다.
- **계정:** `shy61`은 관리자 그룹에 속합니다. 그래서 공개 키는 `~/.ssh/authorized_keys`가 아니라 `C:\ProgramData\ssh\administrators_authorized_keys`에 넣어야 하고, 이 파일의 권한은 Administrators와 SYSTEM만으로 제한해야 합니다(`sshd_config`의 `Match Group administrators`).
- **등록된 키:** 2026-11-07 기준으로 없습니다. 노트북(Ubuntu)도 비밀번호로 접속하고 있습니다. 비밀번호 로그인은 꺼져 있지 않습니다.
- **PC의 호스트 키 지문:** ED25519 `SHA256:V+sfV+6v7EisnnFEcDOFugdQVjmdLTpAv98HFT9R+9Y`
- **시험 기기:** 갤럭시 S22, One UI 8(Android 16)

## 2. 결정

2026-11-07에 사용자와 논의하여 정했습니다.

| 번호 | 쟁점 | 결정 |
|---|---|---|
| 1 | 명령 틀 | memory_tool 실행 방식 하나를 저장합니다. 예: `Set-Location 'E:\…\memory_notion'; python -m memory_tool {args}`. 앱이 명령과 인수를 PowerShell 작은따옴표로 감싸서(안의 `'`는 `''`로) `{args}` 자리에 넣습니다. 처음에는 기록 명령 틀만 저장하려 했으나, 0.2의 보기·수정 명령을 위해 넓혔습니다 |
| 2 | 기록 창을 여는 방법 | 앱 아이콘, 홈 화면 위젯, 빠른 설정 타일, 공유하기. 위젯은 입력칸 모양이고 누르면 홈 화면 위에 작은 입력 창이 뜹니다. 안드로이드 위젯은 글 입력 부품을 쓸 수 없기 때문입니다. 위젯에는 음성 입력 버튼과 보관 상태를 둡니다 |
| 3 | 위치 | 이 저장소의 `android/`. `obsidian-plugin/`, `vscode/`와 같은 memory_tool 클라이언트이고 `--json` 형식에 묶이기 때문입니다. 버전은 CLI와 따로 붙입니다 |
| 4 | 음성 입력 | 받아쓴 글을 3초 동안 보여 주고 보냅니다. 그사이에 누르면 편집 모드로 바뀝니다. 대기 시간은 설정에서 바꿉니다 |
| 5 | 보내지 못한 기록 | 휴대폰에 보관하고 네트워크가 연결되면 자동으로 다시 보냅니다. 적은 시각을 `--date`, `--time`으로 보냅니다. 접속·인증 단계의 실패만 자동으로 다시 보내고, 명령을 보낸 뒤 결과를 받기 전에 끊긴 경우는 "확인 필요"로 표시하여 사용자가 "보냄으로 처리"나 "다시 보내기"를 고릅니다 |
| 6 | 키와 PC 확인 | 앱이 휴대폰 전용 ED25519 키를 만들고, 개인 키는 안드로이드 키 저장소의 키로 암호화해 앱 안에만 둡니다. 공개 키는 복사·공유할 수 있습니다. 처음 접속할 때 PC 지문을 보여 주고 확인을 받아 저장하며, 지문이 바뀌면 보내지 않습니다 |
| 7 | 결과 표시 | 성공은 "21:30 기록함"을 잠깐 띄웁니다. `notices`와 실패는 알림으로 띄웁니다. 다시 보내도 같은 결과가 나오는 실패(`distant_past` 등)는 "확인 필요"로 둡니다. 앱 안에 최근 보낸 기록 목록을 둡니다. `--json` 출력이 아니면 첫 줄을 보여 줍니다 |
| 8 | 지원 기기 | Android 10(API 29) 이상 |
| 9 | 범위 | 0.1 기록, 0.2 타임라인 보기·수정. 모듈 편집은 넣지 않습니다. 0.2의 설계는 0.1을 써 본 뒤 정합니다 |
| - | 설치 | 직접 서명한 APK를 휴대폰으로 옮겨 설치합니다. 사용자가 `mlog.ps1` 같은 PC 쪽 스크립트 없이, 명령을 앱에 저장하는 방식을 골랐습니다 |

**관례에 따라 정한 세부 사항**

- Kotlin, Jetpack Compose. 백그라운드 재전송은 WorkManager(네트워크 연결 조건).
- 화면 언어는 휴대폰 언어를 따릅니다(한국어, 그 밖에는 영어).
- 설정: PC 주소(DDNS), 포트, 사용자, 명령 틀, 음성 대기 시간. PC는 한 대만 지원합니다.
- 서명 키는 저장소 밖에 보관합니다. 업데이트할 때 같은 서명을 써야 앱 데이터가 유지됩니다.
- 빌드 도구는 C 드라이브 여유 공간이 적어(2026-11-07 기준 약 95% 사용) E 드라이브에 설치합니다. 전역 환경 변수는 바꾸지 않고, `android/local.properties`(저장소에 넣지 않음)와 Gradle 설정으로 경로를 지정합니다.

### 설치한 빌드 환경 (2026-11-07)

모두 `E:\dev` 아래에 있으며, 전역 환경 변수와 PATH는 바꾸지 않았습니다. 내려받은 파일은 배포처의 체크섬과 대조했습니다.

| 도구 | 위치 | 버전 | 확인 |
|---|---|---|---|
| JDK | `E:\dev\jdk-17` | Temurin 17.0.21+9 | Adoptium API의 SHA-256 |
| 안드로이드 명령줄 도구 | `E:\devndroid-sdk\cmdline-tools\latest` | 23.0 | Google 저장소 목록의 SHA-1 |
| SDK 플랫폼 | `E:\devndroid-sdk\platformsndroid-36` | API 36(Android 16) | sdkmanager가 확인 |
| 빌드 도구 | `E:\devndroid-sdkuild-tools.1.0` | 36.1.0 | sdkmanager가 확인 |
| platform-tools(`adb`) | `E:\devndroid-sdk\platform-tools` | 37.0.1 | sdkmanager가 확인 |
| Gradle | `E:\dev\gradle-8.13` | 8.13 | services.gradle.org의 SHA-256 |

- 이 버전의 `sdkmanager`는 사용 중단 예정이라는 경고를 내고, 패키지 이름을 `platforms/android-36`처럼 `/`로 표시합니다. Windows의 `.bat`는 `;`를 인수 구분자로 읽으므로, 설치할 때도 `/` 형식을 써야 합니다.
- Android SDK 라이선스는 사용자가 설치를 요청하여 동의했습니다.
- 내려받은 원본은 `E:\dev\downloads`에 있습니다. 필요 없으면 지워도 됩니다.

## 3. 0.1 구현 계획

브랜치는 `feature/android-capture`입니다. 각 단계는 별도의 커밋으로 나누고, 순수 Kotlin 부분은 JVM 단위 테스트로 확인합니다. 기기 화면과 위젯, 타일은 사용자가 휴대폰에서 확인합니다.

1. **빌드 환경:** JDK 17과 안드로이드 명령줄 도구, SDK(플랫폼, 빌드 도구, platform-tools)를 E 드라이브에 설치합니다.
2. **뼈대:** `android/`에 Gradle 래퍼, 앱 모듈, Compose 설정을 만듭니다. `minSdk 29`, `targetSdk`는 설치한 최신 플랫폼으로 합니다.
3. **핵심 논리(안드로이드 API 없음):**
   - PowerShell 인용, 명령 틀 채우기(`{args}`), 기록 인수 만들기(`record --json --date --time -- 내용`)
   - 결과 해석: JSON의 `ok`, `entry`, `notices`, `code`, JSON이 아닌 출력
   - 보관 항목의 상태 전이: 보낼 차례, 보냄, 확인 필요, 실패 종류에 따른 재전송 여부
4. **SSH:** ED25519를 지원하는 라이브러리를 고르고, 키 생성과 암호화 보관, 호스트 키 지문 확인(처음 확인 후 저장, 바뀌면 거부)을 구현합니다. 실패를 "명령 전송 전"과 "명령 전송 후"로 나눕니다.
5. **저장:** 보관 목록과 최근 보낸 기록, 설정을 저장합니다.
6. **입력 창:** 홈 화면 위의 작은 입력 창(투명 액티비티), 음성 입력과 3초 대기, 공유하기 받기.
7. **진입점:** 앱 아이콘, 빠른 설정 타일, 홈 화면 위젯(입력칸 모양, 음성 버튼, 보관 상태).
8. **백그라운드 전송과 알림:** WorkManager 재전송, 성공 문구, 안내와 실패 알림, 알림 권한 요청(Android 13 이상).
9. **설정 화면:** PC 주소, 포트, 사용자, 명령 틀, 공개 키 보기·공유, 지문 확인, 연결 시험 버튼.
10. **서명과 패키징, 문서:** 서명 키 생성(저장소 밖), 릴리스 APK, `android/README.md`, 루트 `README.md`, `CHANGELOG.md`.

**회귀 테스트 필수 사례(JVM)**

- 작은따옴표, 큰따옴표, `$`, `;`, `` ` ``, `%`, 한글, 이모지가 든 내용이 PowerShell 작은따옴표 문자열로 바르게 감싸집니다.
- 줄바꿈은 공백으로 바뀝니다. 타임라인 기록은 한 줄입니다.
- `-`로 시작하는 내용 앞에 `--`가 붙습니다.
- 명령 틀에 `{args}`가 없으면 설정 단계에서 거부합니다.
- 결과 해석: 성공, `notices`가 있는 성공, 실패 코드, JSON이 아닌 출력, 빈 출력.
- 접속 전 실패는 재전송 대상이고, 명령 전송 후 실패와 `distant_past` 등은 "확인 필요"가 됩니다.

**사용자가 휴대폰에서 확인할 것**

1. APK 설치(Play 프로텍트 경고에서 "그래도 설치"가 가능한지)
2. 공개 키를 PC에 등록한 뒤 첫 접속에서 지문이 1절의 값과 같은지
3. 한글과 특수 문자가 든 기록이 PC 타임라인에 그대로 들어가는지(PowerShell과 Python을 거치는 경로)
4. 위젯, 빠른 설정 타일, 공유하기, 음성 입력
5. 비행기 모드에서 기록한 뒤 연결했을 때, 적은 시각으로 들어가는지

**이번 계획에서 하지 않는 것**

- 0.2 타임라인 보기·수정(설계는 0.1 이후), 모듈 편집
- PC 여러 대, Play 스토어 배포
- PC의 비밀번호 로그인 끄기. 휴대폰과 노트북의 키 접속을 모두 확인한 뒤 사용자가 진행합니다
